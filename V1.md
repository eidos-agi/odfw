# ODWF v1 target

**Status:** format roadmap — what the *language* must support so private warehouse packages can solve multi-month warehouse programs  
**Base:** OKF 0.2, ODWF 0.2.x draft
**Private packages:** live elsewhere (never as rich examples in this public repo)

This file is the build target for **public ODWF**. Concrete warehouse packs (SQL, hosts, Excel bytes, results) stay private.

---

## 1. Product thesis

**Canonical intention:** [INTENTION.md](INTENTION.md).

ODWF exists so a **private package** can prove **original spreadsheet → bronze** (self-contained, seeds allowed) and stand as compile input for a later analytics metrics package.

v1 language is complete when a pack can express, validate, and (with external tools) execute:

1. Warehouse topology and honesty (oracle = bronze for this prove path)
2. **Workbook plane** — original starting sheet via explorer sidecars (md5 + facts_digest)
3. Metric/measure definitions with pinned series / grain
4. **SQL packets** and recipes (`basis: bronze` vs seed honesty)
5. **Seeds**, entity-maps, exclusion-sets as first-class concepts
6. **Checks** (sheet vector ↔ bronze; not gold-first)
7. **Tests** and append-only **results**
8. Optional ODCS/datacontract for connectivity — not sheet identity

The format does not run SQL or parse xlsx itself. It **names, links, pins, and fail-closes** so agents and harnesses can.

---

## 2. Why this can work (context for implementers)

- Measured warehouse failures are dense enough to become kinds and gates.
- Sibling OKF profiles (EMF, ORF, OPF) already prove tree + edges + stdlib validators.
- Model judgment is better at multi-constraint fidelity and less premature green.
- Spreadsheet-explorer already solved Excel extraction (facts ≠ judgment, md5 sidecars, never whole sheet).
- Agents can close loops: validate → query → check → write result.

Trust the **package + checker**, not prose alone.

## 4. v1 kind surface (target)

### Already in 0.2.0 draft

`provider`, `layer`, `oracle`, `schema`, `table`, `column`, `entity-map`, `exclusion-set`, `seed`, `pipeline`, `transform`, `recipe`, `measure`, `metric`, `series`, `metric-contract`, `serving-plane`, `publish-path`, `host`, `credential-plane`, `freshness`, `authority-boundary`, `slice`, `acceptance`, `verdict`, `decision`, `risk`, `answer-key`

### Must land for v1 completeness

| Kind | Role |
|---|---|
| `sql-packet` | Named SELECT query packet: basis, grain, params, body or path, links to tables/maps |
| `check` | Executable assertion: peers, compare mode, tolerance, links to contract/packet |
| `test` | Ordered steps binding packets + checks; pass criteria |
| `result` | Append-only run record: digests, outcomes, evidence pointers |
| `workbook` (or strengthen `answer-key`) | Pin to spreadsheet-explorer: source path/name, source_md5, facts_digest, analysis pin, fidelity |

`recipe` may **reference** `sql-packet` rather than inline large SQL in every case.

---

## 5. SQL packets (normative intent)

A sql-packet document MUST carry:

- stable `odwf_id`
- `basis` ∈ {bronze, silver, gold, hybrid, answer-key}
- references to input tables / maps / exclusion-sets where applicable
- grain
- SQL body or relative path under pack `sql/`
- SELECT-only posture (writes are an error at pack policy level)

Validator v1:

- resolve links
- reject secrets/heuristic passwords in packet text
- reject `basis: bronze` with only answer-key inputs (existing recipe rule extended)

Validator does **not** execute SQL against a live DB (harness does).

---

## 6. Checks, tests, results (normative intent)

### Check

- `compare`: vector | scalar (scalar forbidden for operating packs under strict)
- peers: oracle path, live gold, workbook vector (as applicable)
- tolerance mode
- links to metric-contract and/or sql-packet

### Test

- ordered steps
- required verdict class or acceptance status
- links into first_slice where it is the prove path

### Result

- append-only semantics (new file or new log line; no silent overwrite of pass→fail history)
- `at`, `by` (job/agent), packet/check ids, outcome, evidence refs
- optional content digests of SQL text + workbook facts_digest for reproducibility

### Acceptance

- `observed` / `failed` still require evidence (existing)
- v1: evidence may point at `result` ids

---

## 7. Workbook plane (normative intent)

ODWF does not reimplement Excel parsing.

`answer-key` / `workbook` SHOULD declare:

```yaml
tool: eidos-spreadsheet-explorer
source_basename: metrics.xlsx
source_md5: "…"
facts_digest: "…"
manifest_sidecar: "metrics.xlsx.<md5>.json"
analysis_sidecar: "metrics.xlsx.analysis.json"   # optional
fidelity: "source | derivative | …"              # from explorer provenance
```

Gates:

- stale pin (source_md5 mismatch) → warn/error under strict when harness supplies live hash
- analysis without current facts → warn
- values-only / derivative fidelity → cannot be sole basis for `basis: bronze` recipes

Agents query via explorer CLI (`info`, `inputs`, `row N`), never full-sheet ingest.

## 8. Package layout convention (for private packs)

Recommended default (private repos only):

```text
index.md
log.md
concepts/
workbooks/          # xlsx + explorer sidecars
sql/                # packet bodies
checks/
tests/
results/            # append-only
evidence/
```

Public ODWF ships **no** real workbooks/sql/results.

## 9. Validator roadmap

| Phase | Behavior |
|---|---|
| **0.2.0** (now) | Topology, oracle, contracts, serving honesty, recipe basis, acceptance evidence, secrets heuristic |
| **0.2.x v1** | Kinds: sql-packet, check, test, result; workbook pins; edges; result-as-evidence; stricter operating gates |
| **Later** | Optional harness plugins (execute SQL, refresh explorer digests) — out of core format |

Keep validator **stdlib-only** for core gates.

---

## 10. Proof ladder (format + package)

| Level | Claim |
|---|---|
| L1 | Bad packs fail; good packs pass `odwf-validate --strict` |
| L2 | Cold agents with a private package beat agents without on a held-out metric checklist |
| L3 | Production false-green rate drops when the package is the default path |

Public ODWF is responsible for enabling L1. Private packs + harnesses deliver L2/L3.

## 11. Success for ODWF v1 (language)

Public ODWF v1 language surface (0.2.1):

1. [x] SPEC documents sql-packet, check, test, result, workbook pins
2. [x] Validator enforces links, honesty, secrets, vector/strict rules, evidence, SQL posture
3. [x] Private package can express first_slice with packet/check/test/result and validate cleanly
4. [x] `examples/minimal` remains fictional; no production pack in-tree
5. [x] AGENTS.md forbids private pack leakage

Remaining: dogfood live SELECT results (private pack harness), L2 cold-agent proof.

### Testing & connectors (v1 complete / 0.3)

See **[TESTING-AND-CONNECTORS.md](TESTING-AND-CONNECTORS.md)**.

| Default | Choice |
|---|---|
| Contract + quality tests | **ODCS + datacontract-cli** (Ibis backends) — not a new ODWF DSL |
| Optional engines | dbt tests, Great Expectations, SodaCL via `check.engine` |
| Get online (SQL warehouses) | ODCS `servers:` + env secrets; ADBC/SQLAlchemy runtime |
| SaaS extract | Singer / Airbyte (link only) |
| Excel | eidos-spreadsheet-explorer |

ODWF `check`/`test`/`result` **orchestrate and prove**; external engines **execute**.

---

## 12. Non-goals

- Warehouse engine, scheduler, or credential vault
- Executing SQL inside `odwf-validate`
- Parsing xlsx inside ODWF
- Issue tracking or product UX (Linear, OPF)

---

## 13. Implementation order (public)

Language largely landed in 0.2.1–0.2.2. Remaining public work is small and parallel:

1. Keep gates stdlib-only (no live SQL in validate)
2. Optional future `odwf-harness` outside core
3. Second private pack dogfood when a non-Cerebro warehouse exists (portability)
4. Version bumps only for real contract changes

**Instance execution** (metrics, live SQL, L2) lives in private pack plans — e.g. `cerebro-odwf-v1/PLAN.md` phases A–G.
